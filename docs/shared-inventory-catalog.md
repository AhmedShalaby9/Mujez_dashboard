# Catalog and company Inventory

The company sidebar separates two collapsible categories in English and Arabic. Catalog contains Developers, Compounds and Units, using shared platform records. Inventory contains Projects, Units and Reservations, using private company records. Existing read permissions and active subscription checks apply; employee-only accounts do not receive new CRM access.

Company Catalog routes are `/company/catalog/developers`, `/company/catalog/compounds`, `/company/catalog/units` and their `/:id` profiles. They continue using `/api/v1/catalog/{developers,compounds,units}` through `CatalogApi`. Platform admin catalog routes and editor permissions are unchanged. Old company `/developers`, `/compounds` and their profile links redirect to Catalog; old `/company/units/:id` catalog profiles keep the UUID through a redirect. Lead AI recommendations link to catalog profiles.

Company Inventory uses `/company/projects`, `/company/units` and `/company/reservations`. Projects restores the developer/project/phase/building hierarchy and real unit stacking plan. Units restores company unit cards, current status and filters, standalone units, detail drawers and permitted edit/hold actions. Forms for projects, phases, buildings and units reuse the common dashboard styling, versioned API writes and compact monetary input. Reservation and contract links with `?unitId=` now open the actual company unit drawer. Dashboard inventory links also reach company units.

The restored screens use the existing tenant APIs (`projects`, `units`, `reservations`) and do not copy, import or move catalog data. Shared catalog availability does not become a company's reservation state. Each company's stock remains tenant-isolated. No rental-office workflow, new rent status, automatic import, new secret or integration is introduced in this navigation/restoration change.

Catalog lists keep real server pagination, bilingual search, filtering, favorites and UUID profiles. Missing metadata remains "Not set" and images without a source remain explicit placeholders. Existing Jeeran catalog records and AI recommendation data remain intact. Company inventory starts from the company's existing saved stock and shows an honest empty state where none exists.

Validation: `npm run check:overlays`, `npm test -- --watch=false`, and `npm run build`. `inventory.spec.ts` covers shared API rendering and links; `company-inventory.spec.ts` covers restored private project/unit forms, failures, exact prices and actual routing between catalog profiles and private unit links. Navigation tests cover both sales and team-lead access.
